## 1. Determinism (§4.3)

### 1.1 Protocol

The engine's decision surface is pure — no `Math.random()`, no `Date.now()` on any decision
path (verified by grep; the only clock reads are `ageInMonths` inputs, injected by callers).
The test therefore targets *observational* determinism: identical input → identical output,
under repetition, under process restart, and under input key-order permutation.

Eight synthetic caregiver-response profiles were generated by a **seeded** linear congruential
generator (so profile generation is itself reproducible). Each profile is a complete
`AssessmentInput` for age bracket 3-7: 18 item responses, 5 benchmark answers, 11 red-flag
answers, second-adult availability.

Each run's output (the full §8 payload) was hashed two ways:
- **value hash** — SHA-256 of a recursively key-sorted canonicalisation (detects value changes)
- **raw hash** — SHA-256 of `JSON.stringify` (also detects key-ordering instability)

Every third iteration permuted the insertion order of the `responses` object, to probe
sensitivity to JavaScript object iteration order (relevant because the Phase 12 predicate
iterates `Object.keys`).

| Swept domain | Phase range | Monotonic non-decreasing | Distinct phases produced | Transition point(s) |
|---|---|---|---|---|
| `social_communication` | 1 → 5 | Yes | 2 | at 35 (the P1 threshold) |
| `functional_communication` | 4 → 6 | Yes | 3 | at 40 and 60 |

## 3. Comparative evaluation (§4.5) — divergence from a null baseline

**Baseline:** the null (constant) model — every child starts at Phase 1, which is the
behaviour the Compass was designed to replace. No SLP judgments exist; no non-adaptive
version of the engine exists other than this constant function.

**What this measures and does not measure.** The null baseline has no information content, so
disagreement with it cannot be scored as correct or incorrect — there is no ground truth on
either side. The comparison therefore quantifies *divergence*: the extent to which the engine's
output is non-constant, and the shape of that non-constancy. It is a discriminative-behaviour
measure, not an accuracy measure. See §3.7 for the permitted wording.

**Inputs:** 200,000 uniformly-random 7-domain score vectors (0–100 integer per domain), 25%
carrying an oral-motor flag, generated by a seeded LCG. Seed 20260815 is the same run as §2.4
(counts reconcile exactly). Seed 31415926 is an independent replication.

### 3.7 How this may be labelled

**Permitted:** "divergence from a null baseline"; "discriminative behaviour relative to a
constant-placement control"; "the engine assigns a non-Phase-1 starting point to 67.7% of
uniformly-sampled synthetic profiles"; "mean upward displacement of 2.12 phases"; "mean of
10.5 curriculum sessions bypassed relative to sequential delivery".

**Not permitted:** "accuracy", "correct placement", "improvement over baseline", "outperforms",
"validated against", or any wording implying the placements are right. The null baseline is a
degenerate model with no information content; disagreeing with it demonstrates only that the
engine is not itself degenerate. Establishing that the divergence is *in the right direction*
requires a ground truth — SLP placements of the same profiles — which does not exist.

**Sampling caveat that must accompany any use of these numbers:** the input distribution is
uniform over the 7-dimensional score space. Real children do not distribute uniformly, so
every percentage above describes the geometry of the decision rules, not an expected
population outcome. The replication in §3.6 shows the *estimate* is stable; it says nothing
about the *population* the estimate would apply to.

## 4. Data provenance (§4.7) — NOT PATIENT DATA

The hosted database contains: 11 children, 8 assessments, 37 session instances (16 completed),
101 check-ins, 11 phase-history rows, 4 readiness results, 1 placement override, across 4
caregiver accounts.

**This is developer test data, not participant data.** Determining evidence:

- One child record has `dob = 2032-12-13` — a birth date six years in the future.
- One child record has `dob = null`.
- Records were created 1–20 August 2026, exactly spanning the development period, and session
  completions cluster on four dates (7, 14, 20, 22 August) consistent with feature-testing runs.
- Project records describe end-to-end smoke tests run with throwaway authentication users.

Outcome distribution of the 16 completed sessions: 8 `advance`, 7 `retake`, 1 `simplify_triggered`.

**No real participants. No ethics-approved data collection has occurred. The profiles used in
§1 and §2 are synthetic vectors generated for this audit — they are not clinically-designed
simulated patient profiles and were not reviewed by a clinician.**
